# Integration plan: the maths skills chain as a lead magnet on the marketing site

> **Status, 2026-09-22: Phases 0 to 3 are built** on the branch `feat/maths-skills-chain` (not pushed, not deployed). Unit tests, the full Cypress suite against the production build, and a four-device mobile audit all pass.
>
> Built differently from the plan below in three places, each simpler:
> - **React Router:** the component keeps its state under one key of `history.state`, merged with the router's own, so nothing had to move into search params and `RouteTracker` is untouched.
> - **Prerendering:** the component is never rendered on the server. The build writes a plain list of every stage and skill into the page; the browser swaps in the interactive chain. The chain's data is not in the main bundle.
> - **Ownership:** both repos still hold a copy of the component, kept identical. Deleting the simplexResourcesV4 copy remains open.
>
> **Still needs the owner before going live:** the wording in `src/data/skillsChainCopy.js` (decision 1 below: what a diagnostic actually is), and a "Stuck on" column in the Enquiries sheet's Apps Script (the field is already sent; the sheet ignores it until the column exists). The site header's button still reads "Book a free lesson" on this page and scrolls to the diagnostic form.

Written 2026-09-21. For the owner, and for whoever (person or Claude Code session) builds it in this repo.

## 1. What we are shipping, and why

A public page on simplextuition.com.au where a parent, on a phone, sees all of school maths as **one chain** from Kindergarten to Year 12, taps the skill their child is stuck on, and watches the chain underneath it light up: "this rests on 29 earlier skills across 4 stages".

**The job of the page is one thought:** *"I wish someone could tell me exactly where in this chain my child's gaps are."* The next step is **booking an in-person diagnostic**.

**The chain component itself carries no call to action** (owner's decision, 2026-09-21): no Book button, no pitch, no mention of a diagnostic. It is built for a parent on three hours of sleep: about 16 words of introduction, one interaction, one colour. The *page* around it, in this repo, holds the one call to action, underneath the chain.

The chain diagnoses nothing. It must never tell a parent where their child's gap is: no quiz that ends in a verdict, no "start here". Both rules (no diagnosis, no call to action inside the component) are written into the component's header and into simplexResourcesV4's CLAUDE.md, and its audit fails if a link or selling words appear inside it.

## 2. What already exists (nothing here needs inventing)

| Piece | Where | State |

| Mobile audit: 4 device profiles, overflow, 44px targets, clipped text, leaked ids, and every interaction | `simplexResourcesV4/scripts/chain_mobile_audit.py` | Passing on iPhone 13, 360px Android, 320px iPhone SE, landscape; also checked at 125% and 150% text |

The component's props are the whole integration surface:

```jsx
<ParentView
  data={parentsJson}                 // the export
  onEvent={(name, params) => ...}    // chain_year {year} · chain_skill {topic, stage} · chain_path {topic, earlierSkills}
  copy={{ title, lead, pathNote }}   // the only words a parent reads, overridable
/>
```

`onEvent` is how this site's page learns what the parent is looking at, both for analytics and to carry "stuck on: Solving equations" into the lead form.

## 3. Decisions only the owner can make (blockers, in order of urgency)

1. **What is the diagnostic, concretely?** Length, where, price or free, what the parent walks away with. The chain component now says nothing about it, so every word of the offer will be written in this repo, on the page under the chain. Whatever it says must be true. Today the whole site sells **"Book a free first lesson"**, and `/diagnostic` is a **retired page**. Decide how the diagnostic sits beside the free lesson: does it replace it on this page only, or is it the same appointment under a sharper name?
2. **The URL of the chain page.** Recommendation: `/maths-skills-chain`. Do **not** reuse `/diagnostic`: `vercel.json` serves it as a **permanent (308) redirect**, which browsers and Google cache indefinitely, so returning visitors would bounce home even after the redirect is removed.
3. **Book on the page or on another page?** Recommendation: **on the page**, reusing `<LeadForm>` at `#book` directly under the chain, titled "Book a diagnostic". Since the chain has no button of its own, this form (plus the site header's existing Book button) is the only call to action, which keeps it to one. No navigation means no drop-off, and the form already does Formspree, the Enquiries sheet, attribution and `/thank-you`.
4. **Is the diagnostic spec public?** `parents.json` deliberately leaves out the three can-do test statements per skill. Recommendation: keep them private. They are the diagnostic. Publishing them hands the product to competitors and lets parents half-test at home, which answers the question this page exists to raise.
6. **How hard should the page sell?** The owner removed every call to action from the chain. Read that as the brief for the page too: one quiet form under the chain, no pop-ups, no sticky bar, no repeated buttons.
5. **Maths only.** The site sells Maths and English. The chain is maths. The page and its form should say so, and the lead should arrive tagged as a maths enquiry.

## 4. Engineering work, in phases

### Phase 0. Bring the code and data in (half a day)

- Copy `simplexResourcesV4/src/chain/parent/` to `src/chain/` here. From that moment **this repo owns the parent view**; delete it from simplexResourcesV4 (keep the tutor map there, and point its "Parent view" button at the live page) so two copies cannot drift.
- Add `scripts/sync-chain.js` and `npm run sync:chain`: copies `../../simplexSkillsChain/rendered/parents.json` to `src/data/skillsChain.json` and prints the skill count. Vercel cannot see a sibling repo, so the JSON is **committed** here. Updating the chain on the site becomes: render there, `npm run sync:chain` here, commit, deploy.
- Add a Vitest guard, `src/data/skillsChain.test.js`, that fails the build if the file ever contains `can_do`, a NESA code pattern (`MA4-`, `MST-`, `S3-RQF`), `judgment` or `provenance`. This is the tripwire against someone syncing `chain.json` by mistake.

### Phase 1. Make it work inside this site (1 to 2 days). Three real incompatibilities

1. **Prerendering.** `npm run build` renders every route with `renderToString` (`entry-server.jsx`). `ParentView` reads `window.location.hash` inside a `useState` initialiser, which will throw at build time. Fix: move those reads into a mount effect (initial state null, then hydrate), and guard `document`/`window` in `VerticalChain`'s measuring. The chain itself needs a measured width, so it renders client-side only.
2. **What the prerender should output instead.** Do not ship an empty shell to crawlers. Render, server-side, the hero plus a plain semantic list: each stage as an `<h2>`, its introduction, and every skill's sentence as a list item. That is 142 lines of exactly the text parents search for ("what should my Year 5 child know in maths"). The interactive chain replaces it after hydration (`useEffect` sets `mounted`). This is the single biggest SEO win in the project and costs an afternoon.
3. **History and React Router.** `ParentView` calls `history.pushState/replaceState` with its own state object so the phone's Back button leaves path mode. React Router 7 stores its own object in `history.state` and listens to `popstate`; overwriting that state will confuse it. Fix: drive the UI state from the router instead: `useSearchParams` (`?skill=…&view=path`) with `navigate(..., { replace })` for sideways moves and a push for "deeper" moves. The component already separates these two cases in one function (`go`), so the change is contained. Search params (not the hash) also mean `RouteTracker` reports chain interactions as page views unless told not to: exclude the chain's params there.

Also in this phase:

- **Tokens.** `parent.css` reads the resources repo's token names with hex fallbacks, and the hex values are identical to this site's, so it renders correctly untouched. Tidy it anyway: at the top of `.pv`, map to this site's names (`--bg`, `--panel`, `--ink-2`, `--hl`, `--line`, `--kraft-soft`). Same font (Source Sans 3) already loads.
- **`MobileBar` collides with the chain's dock.** Both are fixed to the bottom of a phone. On the chain route: do not render `MobileBar`. It would also put a selling bar over a component the owner asked to keep free of them.
- Route: `<Route path="/maths-skills-chain" element={<SkillsChainPage />} />`, lazy-loaded (`React.lazy`) so the homepage bundle does not grow. Add the path to `PRERENDER_PATHS` and a `chainSeo()` in `src/seo/pages.js` (title, description, canonical, `BreadcrumbList`, and the shared business node).

### Phase 2. The conversion path (1 day)

- `SkillsChainPage` = site `Header` + `<ParentView>` + `<LeadForm id="book" location="skills-chain" title="Book a diagnostic" />` + `Footer`.
- **Carry the context into the lead.** The page keeps the last `chain_skill` / `chain_path` event it received from `onEvent`. Extend `LeadForm` with an optional `context` prop: when the parent has tapped a skill, show it back above the form ("You were looking at: *Solving equations*") and pre-select `yearLevel` from the last `chain_year`, if any (`'8'` → `'Year 8'`; `YEAR_LEVELS` already use that wording). Add `stuckOn` and `earlierSkills` to the Formspree payload and the `_subject` line, and to `buildEnquiry()`.
- **The Enquiries sheet needs a column.** `integrations/enquiries-sheet/` (Apps Script) writes fixed columns. Add "Stuck on" (and optionally "Skills underneath"), and update its README. Until that is deployed the extra fields are ignored harmlessly, because the call is fire-and-forget.
- This is the payoff: the tutor opens the diagnostic already knowing the parent's worry and the 29 skills to test. Say that on `/thank-you` when the lead came from the chain ("We will start with …").
- Analytics: pass `onEvent={trackEvent}`. Funnel to watch in GA4: `chain_year` → `chain_skill` → `chain_path` → `form_started` (already fired by `LeadForm`) → `qualify_lead`. `trackLead` already fires the Meta Pixel `Lead`, so ads can optimise on it. Attribution needs nothing: `attribution.js` classifies the landing touch on any page.

### Phase 3. Tests, in this repo's existing style (1 day)

- **Vitest:** `verticalLayout.js` is pure. Assert for widths 320, 360, 390, 700, 960: no overlapping cards, nothing off-screen, no link pointing upward, path mode returns only the lineage. (These are the checks it was developed against.)
- **Cypress**, new `07-skills-chain.cy.js` at a phone viewport, run in both modes CI already uses (dev and `CYPRESS_PRERENDERED=true`): page has no horizontal scroll; tapping a skill shows the dock with "Rests on N earlier skills"; "See its path" reduces the cards; Back restores them; the form under the chain shows the skill the parent tapped and posts `stuckOn`; no element's text matches an id or syllabus code; **the chain component contains no link, no Book button and none of the words diagnostic, book, enquire** (the same guard its Python audit enforces).
- Extend `06-seo.cy.js`: the prerendered HTML of the chain page contains a Year 5 skill sentence and its own canonical.
- Port `chain_mobile_audit.py`'s ideas (44px targets, clipped text) into the Cypress spec, or keep running the Python audit against `npm run preview` before each release.

### Phase 4. After launch (each optional, each independent)

1. **One page per skill, prerendered** (`/maths-skills-chain/year-8/solving-equations`, 142 pages from the same JSON, like the suburb pages from `locations.js`). Each answers a real search ("year 8 equations what should my child know", "why is my child struggling with fractions") with the sentence, why it matters, what it rests on, and the Book button. This is programmatic SEO with genuinely distinct content per page. Needs a stable slug per skill: add `slug` to `parents.json` in simplexSkillsChain (derive once, then freeze, as ids are frozen).
2. **Tutor-sent links.** `?skill=…&view=path` deep links already work. Give tutors a habit: after a lesson, text the parent the link for the skill they worked on.
3. **Entry points on the rest of the site.** A section on Home ("See the chain"), a line in the FAQ, and the "Marks are slipping a bit" and "The school said something" concern chips can link to it. Ads and QR flyers can land here directly; UTM tags are already understood by `attribution.js`.
4. **"Send me this path"**: email capture as a softer conversion for parents not ready to book. Only if the booking rate shows a gap to fill; it adds a second call to action to a page built around one.
5. **English.** The repo structure supports a second chain. It needs authoring from the English syllabus first, which is its own project.

## 5. Risks

| Risk | Why it matters | Mitigation |
|---|---|---|
| The page over-promises the diagnostic | It is the only thing the page asks for; a parent who books and gets a generic free lesson feels misled | Settle decision 3.1 before launch; write `bookPitch` from what actually happens in the room |
| Someone syncs `chain.json` instead of `parents.json` | Publishes the diagnostic spec and internal notes | The Phase 0 Vitest guard fails the build |
| A future edit "helps" by adding a self-diagnosis quiz, or puts selling back inside the chain | The first removes the reason to book; the second is what the owner explicitly removed | Rule is stated in the component header and in simplexResourcesV4's CLAUDE.md; repeat it in this repo's README when the page lands |
| Two copies of the parent view drift | Fixes land in one place only | This repo becomes the single owner in Phase 0 |
| Bundle weight on the homepage | Site speed is part of local SEO | Route is lazy-loaded; JSON ships only with that chunk |
| The chain is about 12,500px tall on a phone (rows are spaced widely so links can be followed) | Could feel endless | Already handled: pinned year strip jumps anywhere, path mode collapses it to about 30 cards, the prerendered list gives crawlers and no-JS users a readable page |

## 6. Definition of done for launch (Phases 0 to 3)

- `/maths-skills-chain` loads on a mid-range Android over 4G with the chain interactive in under 3 seconds, and scores no accessibility errors in Lighthouse.
- View-source of the deployed page shows real skill sentences, its own title and canonical.
- A test lead submitted from the chain arrives by email and in the Enquiries sheet with channel, year level **and the skill the parent was looking at**.
- GA4 shows the three chain events feeding `form_started` and `qualify_lead`; Meta shows `Lead`.
- `npm test` passes, including the new leak guard, layout tests and the Cypress spec in both dev and prerendered modes.
- The owner has read every sentence a parent can see on the page and would say it out loud.

## 7. Suggested order of work for one Claude Code session in this repo

Phase 0 fully → the three Phase 1 incompatibilities (prerender guard first, since the build fails without it) → route, SEO entry, MobileBar exclusion → Phase 2 form context → Phase 3 tests → open a PR. Stop and ask before changing the Apps Script integration or any copy that describes what the diagnostic includes.
